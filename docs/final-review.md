## 2. 평가 기준 4개 — 점수 (25점 × 4 = 100)

점수는 우리 스스로 매긴 것이다. 다른 팀 결과를 모르니 상대 순위는 추정일 뿐이다.

| 기준 | 근거(강점) | 깎이는 곳 | 점수 |
|---|---|---|---|
| **아이디어 · 서비스 가치** (창의성 · 실용성 · 활용 가치) | 질문 하나("정말 올랐을까")가 분명하고 아무도 세지 않던 것을 셌다. 답이 숫자 하나(−2.4% · 42%)로 떨어진다. 사기 전 두 번 클릭이라는 쓰임이 구체적이다 | 수익 모델이 알림·리포트·API 로 흔하다. 채널 실명 랭킹의 논란 가능성(학습용 고지로 방어) | **22 / 25** |
| **아키텍처 구성 · 이해도** (설계 적절성 · 기술 선택 · 동작 원리 이해) | 서비스 4개 · 스키마 4개 · OpenAPI 명세 4개 + CI(Spectral · oasdiff · 드리프트 테스트). 읽기 GET / 쓰기 배치만 · 외부 API 는 배치에서만. 무료 512MB 때문에 한 프로세스로 합친 이유와 되돌리는 방법을 말할 수 있다. 막힌 것 여섯 가지의 원인·개선을 설명한다(강의계획서 기준 직격) | "한 프로세스면 MSA 냐"는 질문 가능(답 준비됨). 인증은 내부 토큰 하나. 모니터링 없음 | **23 / 25** |
| **데이터 · API 활용** (데이터 처리 · 외부 API 연계 수준) | 공개 API 6개가 각각 다른 질문에 답한다. 영상 45,660 · 시세 290,175 · 공시 49,099 · 언급 50,196. 채널 547개를 API 로 재서 규칙으로 51개 선정. 매칭 26→65%(테마 사전), 사건일 규칙, 벤치마크 대비, 거래량, 공시 동반. 필수 페이지(데이터 탭)가 파이프라인 대시보드 수준 | 제목만 본다(자막 X). 논조는 단어 사전(모델 X). 크롤링은 없음(선택 사항이지만 "또는"이라 감점 아님) | **23 / 25** |
| **발표 완성도** (자료 구성 · 명확성 · 전달력) | 평가 기준 순으로 재구성, 장당 메시지 하나, 글자 대신 숫자·그림, 쇼릴 1분 16초, 단계 등장·코드 단계 강조, 12분 안. 대본에 평가 기준↔장 대응표 | **리허설을 아직 안 했다.** 발표자 1명이라 질의응답 때 다른 팀원이 답할 수 있어야 한다(team-guide 로 준비). Render 콜드스타트(발표 직전 /healthz) | **21 / 25** (리허설 뒤 23) |
| **합계** | | | **89 / 100** → 리허설 뒤 **91~92** |

### 상대 위치 추정
다른 팀의 결과물을 보지 못했으므로 추정이다. 수업 요구(백엔드 + API + 기획, 외부 API 1개 이상, 필수 페이지)를 기준으로 보면, 외부 API 6개 · 1년치 실데이터 · 매일 도는 배치 · 명세 기반 CI · 실패 원인·개선 서사까지 갖춘 팀은 드물 것이다. **상위 10% 안(4~5개 팀 중 1위 후보)** 으로 본다. 1위를 못 받는다면 이유는 내용이 아니라 전달(시간 초과, 질의응답에서 발표자 외 팀원이 못 답함)일 가능성이 가장 크다.

4. 질문이 나오면 부록 19·20장(DB · API)으로 바로 간다(`End` 키 → ←).
