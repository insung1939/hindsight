## 8. 아키텍처 (1:00)

수업 구성 그대로입니다. 프론트는 **Vercel** 의 React, 백엔드는 **Render** 의 FastAPI, DB 는 **Supabase** PostgreSQL, 코드와 배치는 **GitHub**.

백엔드는 서비스 4개로 나뉩니다. market-data(사전·시세·공시), youtube(채널·영상), mentions(제목→종목·논조), stats(수익률·랭킹). 각자 자기 스키마와 OpenAPI 명세를 갖고, 서로는 REST 로만 부릅니다. 다만 무료 Render 가 512MB 라 한 프로세스에 네 앱을 마운트했고, Swagger 도 /docs 하나에 합쳤습니다.

데이터 흐름은 두 갈래입니다. **배치**는 Actions 가 /internal/sync 를 토큰으로 호출해 외부 API 를 읽고 DB 에 씁니다. **화면**은 GET 만 부릅니다. 예를 들어 "언급 뒤에" 탭을 열면 브라우저가 `GET /stats/v1/summary?scope=overall&horizon=20&stance=bull` 을 부르고, FastAPI 가 `stats.summaries` 테이블에서 키 하나를 읽어 JSON 으로 돌려줍니다. 외부 API 는 요청 때 부르지 않습니다. 그래서 화면이 빠릅니다.

## 9. 화면 (0:15)

화면은 다섯 개입니다. 홈은 지금 유튜브에서 뜨는 종목, "언급 뒤에"는 5·20·60일 분포와 시장 대비, 채널은 TOP 3·BOTTOM 3 와 채널별 상세, 종목은 주가 위에 언급 시점을 찍은 차트, 데이터는 파이프라인 실건수와 출처입니다. 프론트는 평가 제외라 들었기 때문에 화면은 API 를 읽기만 합니다.

## 10. 결과 ① (1:00)

이제 질문의 답입니다. [카드 가리키며] 낙관 언급 뒤 **20거래일** 평균 수익률 **−2.4%**, 오른 비율 **42.5%**, 시장 대비 **−2.8%p**. 표본은 **1만 3천 건**.

분포를 보시면 왼쪽 파랑이 하락, 오른쪽 빨강이 상승인데 왼쪽이 더 큽니다. 세 가지로 읽습니다. 상승 확률이 50% 아래면 언급 뒤에 사면 내린 쪽이 많았다는 뜻이고, 시장 대비가 음수면 시장을 따라가지도 못했다는 뜻이고, 거래량 비율 0.92 는 거래가 언급 **전**에 몰렸다는 뜻입니다.

## 11. 결과 ② (0:35)

시장별로 보면 국내·미국·코인 모두 같은 방향입니다. [표의 시장 대비 열 가리키기]
채널별로는 다릅니다. 낙관 언급 30건·10종목 이상인 채널만 순위에 올렸는데, 시장을 **+5%p** 이긴 채널도 있고 **−18%p** 뒤진 채널도 있습니다. 채널 이름은 실명으로 보여줍니다. 서비스에서 채널을 누르면 5·20·60일을 바꿔 가며 볼 수 있습니다.

## 12. 발견 (0:35)

숫자가 말해 준 걸 다섯 줄로 정리했습니다. [카드 1~5 를 그대로 읽되 각 한 문장]
1. 20일 평균 −2.4%, 상승 42.5% — 언급 뒤에 사면 내린 쪽이 많았다.
2. 시장을 빼면 −2.8%p — 시장도 못 따라갔다.
3. 거래량은 언급 앞이 더 많았다 — 관심이 먼저, 유튜브는 뒤따른다.
4. 5일 → 20일 → 60일로 갈수록 시장과 더 벌어진다.
5. 국내 언급의 일부만 사건일 ±3일에 주요 공시가 있었다 — 대부분은 공시와 무관했다.

이건 1년, 채널 51개, 제목만 본 범위 안의 결과이고 투자 권유가 아닙니다.

## 13. 한계 (0:30)

이 숫자가 말하지 않는 것도 적어 뒀습니다. [카드 1·6 은 꼭, 나머지는 한 호흡]
- **제목만 봅니다.** 자막·설명은 안 모았습니다. 제목에 종목이 없는 "이 종목 지금 사야 합니다" 같은 영상은 놓치고, "지금 사도 될까?" 같은 질문형은 낙관으로 잡힐 수 있습니다.
- 낙관·비관은 **단어 사전**으로 가릅니다. 모델이 아닙니다. 그래서 근거 단어를 화면에 그대로 보여 주고 검수를 돌리고 있습니다.
- 1년, 채널 51개라는 **범위** 안의 결과이고, 같은 날 여러 채널이 같은 종목을 말하면 **표본이 독립이 아닙니다**.
- 종가 기준이고 **거래 비용이 없는** 수익률이라 실제는 더 낮습니다.
- 마지막으로 이건 **상관**이지 인과가 아닙니다. 유튜브가 내리게 한 게 아니라, 이미 오른 뒤에 언급이 몰리는 구조가 가장 그럴듯한 설명입니다.

## 14. 한 문장 (0:20)

한 문장으로 줄이면, **"유튜브가 오른다고 할 때는 이미 늦었다."**
그래서 이 서비스가 하는 일은, 영상이 말한 종목을 사기 전에 그 종목이 전에 떴을 때 어땠는지 먼저 보게 하는 겁니다.

## 15. BM (0:30)

누구에게 쓰이나. 개인투자자는 영상을 보고 사기 전에 두 번 클릭 — 종목 페이지에서 "전에 떴을 때 어땠나", 채널 페이지에서 "이 채널 말은 맞았나". 증권사 리서치·콘텐츠팀은 채널별 적중 기록으로 출연자나 인용 채널을 고를 수 있습니다.
수익은 관심 종목 언급 급증 알림 구독, 채널 적중 리포트, 언급량 데이터 API. 운영비는 무료 티어와 하루 1회 배치로 거의 0 입니다. YouTube 쿼터도 하루 300유닛이면 됩니다.

## 16. 실패·개선 (0:40)

막혔던 것 여섯 가지입니다. [카드 순서대로, 각 한 문장]
- 매칭 26% → 못 잡은 제목을 읽고 테마 사전 → 65%.
- 낙관 오탐 — "급등했던 이유" 같은 사후 해설이 낙관으로 잡혀서, 과거 단서만 있으면 중립으로.
- Render 512MB OOM — 프로세스 5개를 1개로, DART 3,998건은 스트리밍 파싱, 사전 갱신은 주 1회.
- Supabase 연결 15개 한도 — 엔진당 풀 1개, 긴 배치는 백그라운드 + 상태 폴링.
- 공공데이터포털 "미등록 키" — 키가 아니라 옛 V1 주소가 문제였고, V2 로 고치고 실패 시 Yahoo 로 대체.
- 크롤링 — 네이버 증권 뉴스 기사 수를 넣었다가 뺐습니다. 필수가 아니었고, 소급이 안 되고, 비공식 엔드포인트라 설명이 길어져서요. 같은 질문은 DART 공시로 답합니다.

## 17. 우리만의 것 (0:30)

요구사항 위에 더한 것 여섯 가지입니다. 방금 보신 **쇼릴**, 매일 스스로 도는 **파이프라인**, 명세를 먼저 쓰고 CI 가 지키는 **OpenAPI 계약**, 서비스 4개를 한 프로세스에 넣은 **MSA**, 사건일·벤치마크·거래량·공시·논조 같은 **금융 데이터의 디테일**, 그리고 채널까지 **데이터로 고른 것**.

스키마 4개, 테이블 9개. 같은 스키마 안에서는 FK(videos → channels), 스키마 사이에는 FK 를 걸지 않고 id 만 보관합니다 — 서비스를 따로 배포해도 깨지지 않게요. 핵심 관계는 영상 1 → 언급 n → 수익률 1. mentions 는 (video_id, asset_id) 유니크, event_returns 는 mention_id 유니크입니다.

## 부록 20. API (질문 나오면)

읽기는 GET /v1/*, 쓰기는 /internal/sync 뿐이고 토큰이 필요합니다. 요약 하나 받는 예: `GET /stats/v1/summary?scope=overall&horizon=20&stance=bull` → n, mean, win_rate, excess_mean, histogram. 수익률은 소수(0.024 = 2.4%), 오류는 RFC 9457 problem+json, 응답마다 X-Request-ID, GET 은 Cache-Control 10분. 명세는 contracts/*.yaml 이고 Spectral 과 oasdiff 가 CI 에서 검사합니다.

## 예상 질문 짧은 답

- **통계적으로 유의한가?** 20일 초과수익 −2.8%p, n=13,482, 표준편차 약 20%p → 표준오차 0.17%p, t ≈ −16. 유의합니다. 다만 사건이 같은 날 겹치므로(클러스터) 보수적으로 봐야 합니다.
- **왜 1년, 왜 5·20·60일?** 1년은 YouTube 쿼터·시세 소급·최근성의 타협. 5·20·60 은 1주·1개월·3개월에 해당하는 관행적 구간. 1~120일 곡선을 그려 봤고 어느 구간에서도 결론이 바뀌지 않았습니다(docs/decisions.md).
- **제목만 보는 건 한계 아닌가?** 맞습니다(13장). 자막·설명은 수집하지 않았습니다. 대신 제목은 가장 많은 사람이 보는 한 줄이고, 분류 근거 단어를 화면에 그대로 보여줍니다. 다음 단계는 설명란·자막을 같은 파이프라인에 태우는 것입니다.
- **낙관으로 잘못 분류된 건?** 사후 해설 규칙으로 1,284건을 걸렀고, 100건 무작위 검수는 진행 중입니다.
- **크롤링은 왜 뺐나?** 16장. 필수가 아니고, 소급이 안 되고, 비공식 엔드포인트. 코드는 커밋 기록에 남아 있습니다.
- **팀원 분담은?** 김지환 유튜브 수집·채널 선정, 오선호 종목 매칭·논조, 채재희 시세·통계, 김현준 데이터 출처·문서·BM, 조인성 아키텍처·배포·화면·쇼릴. README 에 표가 있습니다.
