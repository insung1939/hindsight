# 팀원용 안내 — HINDSIGHT 가 뭐고 어떻게 돌아가나 (개발 몰라도 되는 버전)

5조 팀원에게 공유하는 설명서. 코드는 몰라도 이 문서만 읽으면 발표에서 자기 영역을 말할 수 있게 썼다.

## 1. 한 문장
**유튜버가 "오른다"고 한 종목이 정말 올랐는지, 1년치 영상으로 세어 본 서비스.**
주식·코인 유튜브 채널 51개의 영상 제목을 모아, "오른다·급등·매수·기회" 같은 말이 붙은 종목을 찾고, 그 뒤 5·20·60거래일(1주·1개월·3개월) 동안 주가가 어떻게 됐는지 통계로 보여준다.

## 2. 왜 만들었나
"지금이 매수 타이밍!" 영상을 수십만 명이 본다. 맞으면 기억하고 틀리면 잊는다. 그래서 유튜브가 오른다고 한 종목이 평균적으로 어떻게 됐는지 아무도 모른다. 우리는 그걸 숫자로 답한다.

## 3. 데이터가 흐르는 길 (매일 아침 7시 10분, 자동)
택배가 창고를 거쳐 가듯 다섯 단계를 지난다. 사람이 손대는 일은 없다.

1. **영상 수집** — YouTube(구글)에 "이 채널 새 영상 뭐 있어?"라고 물어 제목·게시일·조회수를 받는다. 51개 채널, 1년치 44,600편.
2. **종목 찾기 + 논조 판정** — 제목에서 종목 이름과 별칭(삼전 → 삼성전자, 하닉 → SK하이닉스, 엔비디아 → NVDA)을 찾는다. 상장사 이름은 금융감독원(DART)에서 받고, 별칭과 업종(반도체·2차전지 …)은 우리가 사전을 만들었다. 동시에 제목이 "오른다" 쪽인지 "내린다" 쪽인지 단어로 가른다. 우리는 "오른다" 쪽만 쓴다.
3. **주가 붙이기** — 국내 종가·거래량은 공공데이터포털(금융위원회), 미국은 Yahoo, 코인은 업비트에서 받는다. 국내 종목의 공시(실적·계약 …)는 DART, 뉴스 기사 수는 네이버 증권 페이지를 읽어 온다(크롤링).
4. **수익률 계산** — 영상을 보고 처음 거래할 수 있는 날의 종가를 기준으로, 5·20·60거래일 뒤 종가와 비교한다. 같은 기간 시장(코스피·S&P500·비트코인)이 얼마나 올랐는지도 빼 본다(시장 대비).
5. **화면** — 계산된 결과만 보여준다. 그래서 화면은 빠르다.

## 4. 화면 다섯 개
| 탭 | 보여주는 것 |
|---|---|
| 홈 | 지금 유튜브가 오른다고 하는 종목(최근 7·14·30일), 옆에 "전에 떴을 때 어땠나" |
| 언급 뒤에 | 1년치 전체의 성적표. 평균·상승 확률·시장 대비·거래량·공시 동반, 시장별·업종별 |
| 채널 | 어느 채널이 오른다고 한 종목이 잘 갔나. TOP 3 · BOTTOM 3, 50개 전체 순위, 채널 누르면 상세 |
| 종목 | 종목 하나의 주가 선 위에 언급 시점을 점으로. 공시·뉴스도 함께 |
| 데이터 | 어디서 얼마나 가져왔고 어떻게 가공했는지(평가 필수 페이지) |

## 5. 숫자 읽는 법
- **언급**: 제목에 종목이 나온 영상 한 건. 영상 하나에 여러 종목이면 여러 건.
- **20거래일 수익률**: 언급일 종가 → 20거래일 뒤 종가 변화율. 주말·휴장은 안 센다.
- **상승 확률**: 수익률이 0보다 큰 언급의 비율. 50%면 동전 던지기.
- **시장 대비**: 같은 기간 시장 수익률을 뺀 값. 0 근처면 "시장이 올라서 오른 것".
- **거래량 비율**: 언급 뒤 5일 평균 거래량 ÷ 언급 전 20일 평균. 1보다 작으면 거래는 언급 전에 이미 몰렸다.
- **표본(n)**: 계산이 끝난 언급 수. 30건 미만은 참고용.

## 6. 지금까지 나온 결론 (발표의 핵심)
"오른다"고 한 언급 뒤 20거래일: 평균 **−2%대**, 상승 확률 **43%**, 시장 대비 **−3%대**, 거래량은 언급 **앞**이 더 많음(0.92배).
→ **유튜브가 "오른다"고 할 때는 이미 늦었다.** 영상이 말한 종목을 사기 전에 그 종목이 전에 떴을 때 어땠는지 보라는 것이 이 서비스가 하는 일.

## 7. 무엇으로 만들었나 (스택을 쉽게)
| 역할 | 도구 | 비유 |
|---|---|---|
| 화면 | React (Vercel 에 배포) | 가게의 진열대 |
| 계산·API | Python FastAPI (Render 에 배포) | 주방. 네 명의 요리사(수집·사전·매칭·통계)가 한 주방에서 일한다 |
| 저장 | PostgreSQL (Supabase) | 창고. 요리사마다 자기 선반(스키마)만 쓴다 |
| 자동 실행 | GitHub Actions | 매일 7:10 알람 시계. 주방에 "일 시작해"라고 전화한다 |
| 코드 보관 | GitHub | 설계도 보관함. 바꾸면 진열대와 주방이 자동으로 갱신된다 |

외부에서 받아오는 곳 7개: YouTube · DART(사전·공시) · 공공데이터포털(국내 시세) · Yahoo(미국·지수·업종 ETF) · 업비트(코인) · 네이버 증권(뉴스, 크롤링).

## 10. 예상 질문과 답
- **제목만 보는데 의미가 있나?** → 제목에 "오른다" 쪽 말이 있는 것만 센다. 영상 내용(자막)은 안 본다. 제목이 그 영상의 주장이고, 시청자가 보는 것도 제목이다.
- **채널은 왜 이 51개인가?** → 사람이 고른 게 아니라 후보 547개를 구독자·업로드·종목 언급률·쇼츠 비율로 재서 규칙으로 걸렀다. 구독자 373만 채널도 제목에 종목이 2%면 빠졌다.
- **오탐은?** → 긴 이름 우선, 흔한 단어 금지, 한글·영문 단어 경계 규칙에 테스트 18개. 못 잡은 제목은 버리지 않고 화면에 보여준다.
- **왜 1년, 왜 5·20·60일?** → docs/decisions.md 에 표와 함께.
- **투자 조언 아닌가?** → 추천 문구 없음, 표본 수 항상 표시, 학습용 고지 고정.

## 11. 솔직한 한계
제목 단어로 논조를 가르니 반어·은유는 틀린다. 뉴스는 소급이 안 되어 2주치뿐이다. 채널 순위는 시장·종목이 달라 실력 비교가 아니다. 무료 서버라 15분 쉬면 첫 접속이 30초쯤 걸린다.
