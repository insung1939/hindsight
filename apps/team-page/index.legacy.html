왜 이 주제인가

우리 모두 한 번쯤 겪어 본 장면

  1. STEP 1

    투자 공부는 유튜브로 한다

    주식·코인 정보를 유튜브에서 얻는 사람이 늘었다. "주식 코인 전망"만 검색해도 "지금이 바로 매수 타이밍!", "비트코인 곧 폭등합니다!"가 쏟아진다.

  2. STEP 2

    유튜버는 종목을 콕 집어 말한다

    제목과 썸네일에 종목 이름과 방향이 그대로 들어 있다. "이 종목, 곧 폭등합니다!" 구독자 100만 명이 같은 말을 듣는다.

    "진짜 타도 되는 거야?"
  3. STEP 3

    보는 사람은 살까 말까 고민한다

    지금 살까, 더 지켜볼까, 팔아야 하나. 판단 근거는 방금 본 영상의 분위기뿐이다. 그 유튜버가 전에 한 말들이 어떻게 됐는지는 알 수 없다.

그리고 결과는 둘 중 하나

둘은 기억에 남는 방식이 다르다
▲ 오르면

"역시 유튜버 말이 맞았어!"

맞은 경우는 오래 기억되고, 다음 영상도 믿게 된다.

▼ 떨어지면

"다음엔 잘되겠지…?"

틀린 경우는 금방 잊힌다. 그리고 다음 로켓에 또 올라탄다.

맞으면 기억하고, 틀리면 잊는다.
그래서 유튜브가 언급한 종목이 평균적으로 어떻게 됐는지, 아무도 모른다.

우리는 이 질문에 숫자로 답하려 한다. 개별 영상이 맞았는지가 아니라, 언급이 몰린 뒤 실제로 무슨 일이 있었는지.

해결하려는 문제

영상 보고 사는 사람은 많은데, 그 뒤를 확인하는 사람은 없다

그래서 투자 판단이 과거 기록이 아니라 영상의 분위기와 기억에 기대게 된다. 게다가 언급이 몰리는 시점은 이미 주가가 오른 뒤인 경우가 많다.

누구의 문제인가

  • 유튜브로 정보를 얻는 개인투자자"삼성전자, 지금 사도 될까?" 영상을 보고 매수를 고민한다. 필요한 건 이 종목이 전에 유튜브에서 몰렸을 때 그 뒤에 어땠는지다.
  • 금융 콘텐츠에 관심 있는 학생·연구자유튜브 언급이 주가에 앞서는지, 뒤따르는지 궁금하다. 필요한 건 언급 시점과 주가를 한곳에 모은 데이터다.

지금은 어떻게 하고 있나

  • 영상 댓글, 커뮤니티 후기기억과 분위기에 의존한다. 맞았던 사례만 회자되고 틀린 사례는 잊힌다.
  • 직접 차트를 찾아보기영상 하나마다 날짜를 맞춰 찾아야 해서 여러 건을 모아 보기 어렵다.
  • 증권사 리포트 적중률 서비스기관 리포트만 다루고 유튜브는 대상이 아니다.

우리가 만드는 것

표본 수를 항상 공개

적은 표본의 평균은 오해를 부른다.

통계 옆 n 표시, 5건 미만은 분포 생략

무엇이 다른가

  • 사후 검증. 영상이 말한 미래가 아니라, 영상 이후 실제로 일어난 일을 보여준다.
  • 시장 대비. 시장 전체가 오른 덕분인지 구분하려고 비교 지수 수익률을 뺀 초과수익을 함께 보여준다.
  • 자동 누적. 매일 새 영상과 시세가 쌓여 표본이 계속 늘어난다.

사건만 바꾸면 같은 틀로 돈다

  • 트윗. 트럼프가 "비트코인"을 언급한 뒤 비트코인, "관세"를 말한 뒤 반도체·자동차 업종
  • 뉴스 헤드라인. 특정 종목이 헤드라인에 오른 뒤의 주가
  • 증권사 리포트. 목표가 상향 리포트 발표 뒤의 주가

기대 효과

  • 사용자: 영상의 분위기 대신 과거 기록을 보고 판단할 근거가 생긴다.
  • 팀: 외부 API 수집, 배치, DB 설계, REST API, 프론트 배포까지 수업 전 과정을 하나의 서비스로 연결한다.

쓰기는 배치만

사용자가 데이터를 바꿀 경로가 없어 구조가 단순하고 안전하다. API 서버는 읽기 전용 DB 계정으로 접속한다.

계산은 미리

수익률은 배치가 계산해 저장하고, API는 집계만 한다. 무료 서버에서도 응답이 빠르다.

수업 구성 그대로

Vercel·Render·Supabase·GitHub에 스케줄러로 GitHub Actions만 더한다. Render 무료 플랜은 크론 작업을 지원하지 않기 때문이다.

서비스 흐름

사용자는 두 번 클릭으로 과거 기록에 닿는다

  1. Vercel 주소로 접속하면 홈(이번 주 언급 급증)이 열린다.
  2. 급증 목록에서 종목을 누르거나 검색창에 이름·줄임말을 입력한다.
  3. 종목 타임라인에서 주가 위의 언급 점과 이 종목의 언급 뒤 분포 요약을 본다. 5·20·60일 탭으로 기간을 바꾼다.
  4. '언급 뒤에' 화면에서 시장 전체 분포와 비교한다. 메뉴에서 바로 들어갈 수도 있다.

화면 파일은 Vercel에서 먼저 받아 뜨고, 데이터는 API 두 개를 동시에 호출해 채운다. API 서버는 필요한 행만 읽어 JSON으로 돌려준다.

  1. 홈에서 '삼성전자 · 12건'처럼 이번 주 언급이 늘어난 종목과, 옆에 붙은 '과거 20일 평균 −6.5%'를 본다.
  2. 종목을 누르면 타임라인으로 이동한다. 점 위에 마우스를 올리면 날짜, 채널(A·B·C), 20일 뒤 수익률이 뜬다.
  3. 기간 탭(5·20·60일)을 누르면 분포와 점 색이 그 기간 기준으로 바뀐다.
  4. 표본이 5건 미만인 종목은 분포 대신 "표본이 적어 개별 기록만 보여줍니다"라고 안내한다.

API 공통 규칙

  • 형식: 요청은 쿼리 파라미터, 응답은 JSON (UTF-8).
  • 날짜: ISO 8601. 날짜만이면 2026-09-29, 시각은 2026-09-29T19:00:00+09:00.
  • 수익률: 소수로 준다. 0.038은 3.8%이며 화면에서 퍼센트로 바꾼다.
  • 오류: 항상 {"detail": ...} 모양. 상태 코드는 위 오류 응답 표를 따른다.
  • 캐시: 데이터가 하루 한 번 바뀌므로 GET 응답에 Cache-Control: max-age=600을 붙인다.
  • 서버 깨우기: Render 무료 서버는 15분간 요청이 없으면 잠든다. 프론트는 첫 요청에 30~60초 걸릴 수 있다고 안내하고 재시도한다.

데이터베이스 · Supabase

영상 하나에 언급 여러 개, 언급 하나에 수익률 한 줄

  • 수집(channels, videos), 사전(tickers, ticker_aliases), 시세(prices), 분석(mentions, mention_returns)
  • 계정 둘: batch_writer(배치 전용 쓰기), api_reader(API 전용 읽기)
  • Supabase 공개 Data API로는 접근하지 못하도록 모든 테이블에 RLS를 켠다.
관계종류의미
channels → videos1 : N채널 하나에 영상 여러 개
videos → mentions1 : N영상 하나의 제목에 종목 여러 개가 나올 수 있다
tickers → mentions1 : N종목 하나가 여러 영상에서 언급된다
mentions → mention_returns1 : 1언급 하나에 수익률 한 줄
tickers → ticker_aliases1 : N종목 하나에 별칭 여러 개 (삼성전자, 삼전, 삼성)
tickers → prices1 : N종목·지수 하나에 날짜별 종가 여러 개
tickers → tickersN : 1종목마다 비교할 지수 하나 (삼성전자 → 코스피)

SELECT r.r20, r.ex20
FROM mention_returns r
JOIN mentions m ON m.id = r.mention_id
JOIN tickers  t ON t.id = m.ticker_id
WHERE t.symbol = '005930'
  AND r.r20 IS NOT NULL;      -- 20일이 지난 언급만 표본에 넣는다

    완료 기준무작위 100건을 사람이 검수해 매칭 오류를 잡고, 오류 유형을 사전에 반영

  4. 7주차API와 화면
    • FastAPI 조회 API 6개 Render 배포
    • 화면 3개 Vercel 배포·연동
    • GitHub Actions 매일 자동 실행

    완료 기준배포 주소에서 세 화면이 실제 데이터로 동작한다

  5. 8주차최종 발표
    • 표본 부족 처리, 오류 수정, 화면 다듬기
    • 발표 자료와 시연 리허설
    • 최종 발표

    완료 기준라이브 시연: 종목 검색 → 언급 뒤 분포 → 타임라인

중간 점검

  • 5주차 끝: 데이터가 모이는가. 모자라면 채널 수를 줄이거나 기간을 늘린다.
  • 6주차 끝: 매칭 정확도가 쓸 만한가. 부족하면 대상 종목을 시가총액 상위로 좁힌다.
  • 7주차 중간: 배포 주소에서 API 1개와 화면 1개가 먼저 연결되는가. 나머지는 같은 방식으로 복제한다.

팀 논의가 필요한 항목

다음 회의에서 정할 것

  1. 채널 20개 선정 기준: 구독자 수 상위로 뽑을지, 주식·코인·해외주식을 고르게 섞을지.
  2. 미국 종목 포함 범위: 국내 채널이 자주 다루는 미국 종목만 할지, 전부 할지.
  3. 급증 기준: 직전 4주 평균의 몇 배부터 '급증'으로 볼지, 최소 언급 수를 둘지.
  4. 투자 조언처럼 보이지 않게 하는 장치: 안내 문구 외에 무엇이 더 필요할지.
  5. 역할과 담당자 확정, 주간 회의 요일.
