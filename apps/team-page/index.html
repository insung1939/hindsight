문제

영상 보고 사는 사람은 많은데,
그 뒤를 확인하는 사람은 없다

"지금이 바로 매수 타이밍!" 같은 제목을 수십만 명이 본다. 오르면 "역시 맞았어"로 기억되고, 떨어지면 잊힌다. 그래서 유튜브가 언급한 종목이 평균적으로 어떻게 됐는지 아무도 모른다.

누구의 문제

유튜브로 정보를 얻는 개인투자자. "삼성전자, 지금 사도 될까?" 영상을 보고 매수를 고민하는 사람.

지금은 어떻게

댓글과 기억에 의존한다. 영상 하나하나 날짜를 맞춰 차트를 찾아보는 건 현실적으로 불가능하다.

데이터 활용 기획 시나리오

질문 하나를 데이터 다섯 가지로 답한다

사용자의 질문은 "이 유튜버가 말한 뒤에 어떻게 됐나"다. 우리는 개별 영상이 맞았는지가 아니라 언급이라는 사건 뒤에 실제로 무슨 일이 있었는지를 숫자로 보여준다. 방향(사라·팔아라)은 판단하지 않는다.

데이터 수집 ① 채널

채널은 사람이 고르지 않았다 — 547개를 재서 51개

YouTube 검색으로 후보를 모은 뒤 채널마다 최근 50편 제목을 우리 매칭기로 돌려 구독자 · 주당 업로드 · 종목 언급률 · 쇼츠 비율을 쟀다. 임계값을 바꿔 가며 테스트하고 두 단계 규칙으로 정했다.

후보 → 측정 → 채택

547 → 272 → 51

주식 38 · 코인 13. 방송사·증권사·거래소 공식 채널 제외.

A단 · 대형 영향력

100만구독자 이상

언급률 15% 이상. 삼프로TV(22%)·김작가TV(28%)처럼 시황이 섞여도 한 번의 언급이 닿는 사람이 많다.

B단 · 종목 집중

30%언급률 이상

구독자 주식 5만·코인 10만 이상, 주당 35편 이하, 쇼츠 50% 이하. 규모는 작아도 제목에 종목을 콕 집는 채널.

왜 두 단계인가

언급률 30%만 쓰면 수백만 구독자 채널이 전부 빠지고, 구독자만 쓰면 시황·예능 채널이 들어온다. 구독자 373만 채널도 제목에 종목이 2%뿐이라 제외됐다.

쿼터 설계

YouTube 는 하루 10,000유닛. search.list 는 100유닛이라 후보 수집에만 썼고(1,800유닛), 백필은 playlistItems 1유닛으로 1년치 4만 4천 편을 약 1,500유닛에 받았다.

근거와 전체 표: docs/channel-selection.md · 스크립트 scripts/discover_channels.py. 서비스에서는 채널 실명과 채널별 성적(상·하위)을 보여주되 학습용 통계임을 고지한다.

매칭 규칙 (mentions/matcher.py)

사전(이름·별칭)을 긴 표현부터 정확 매칭("삼성전자우"가 "삼성전자"보다 먼저), 잡힌 구간은 지워 중복 방지. 흔한 단어(삼성·KT·은행)는 단독 금지, "한국은행" 같은 표현은 먼저 제거. 코인은 문맥 단어가 있을 때만.

테마 사전 — 성공률 26% → 62%

못 잡은 제목을 뜯어 보니 대부분 "반도체 급등", "코스피 폭락"처럼 종목 없이 업종만 말했다. 업종 20개를 대표 ETF(KODEX 반도체 등)에 매핑해 사건으로 센다. 종목 통계와는 분리 집계.

T0 규칙 — 처음 거래할 수 있는 날

국내 15:30 KST 전 게시면 그날 종가, 뒤면 다음 거래일. 미국은 동부 16:00, 코인은 업비트 일봉(09:00 KST). rh = P(T0+h)/P(T0) − 1, 초과수익 = rh − 벤치마크 rh.

서비스 간 FK 를 안 거는 이유

각 서비스가 자기 스키마만 쓰고 남의 데이터는 REST 로만 읽는다. 다른 서비스 id 는 문자열로 보관. 분리 배포(k8s)로 옮겨도 DB 를 쪼갤 수 있다.

채널 실명

처음엔 익명(A·B·C)으로 설계했지만, 사용자가 적은 학습 프로젝트라 실명과 채널별 성적을 보여주기로 했다. 대신 "누가 틀렸나"가 아니라 "유튜브 언급을 따라가면 어떻게 되나"를 보는 통계임을 고정 고지한다.

주요 페이지 및 기능

다섯 화면, 전부 계산된 결과만 읽는다

구현

홈 · 지금 뜨는 종목

서비스 설명과 수집 규모, 최근 7·14·30일 언급 급증 종목(시장·테마 필터). 옆에 과거 언급 뒤 20일 평균.

구현

채널

채널별 언급 뒤 성적 TOP 3 · BOTTOM 3, 전체 50개 랭킹 막대 차트(초과수익·평균·상승확률 기준, 표본 30건 이상).

구현 · 수업 필수 분석

언급 뒤에

5·20·60일 수익률 분포, 상승 확률, 벤치마크 대비 초과수익, 거래량 반응, 공시 동반. 범위: 전체·국내·미국·코인·업종테마. 용어마다 설명 툴팁.

구현

종목 타임라인

주가 선 위에 언급 시점을 점으로(색 = 20일 뒤 상승·하락). DART 공시는 눈금으로. 언급별 표에 거래량 비율.

구현 · 수업 필수 데이터

데이터

파이프라인 5단계의 실제 건수, 출처 6개와 현재 상태, 채널 선정 규칙, 매칭 규칙, 못 잡은 제목 20개.

예정 종목 검색 → 별칭 보강 제안

못 잡은 제목에서 자주 나오는 명사를 뽑아 사전 후보로 올린다.

예정 언급 급증 알림

관심 종목의 언급이 직전 4주 평균의 N배를 넘으면 알림(구독 모델).

확장 사건 출처 교체

같은 틀에 트윗·뉴스 헤드라인·리포트 목표가 상향을 사건으로 넣는다.

유튜브 언급을 따라가면, 평균적으로 어떻게 되나

종목·코인 언급 전체(테마 제외). 기간이 지나 수익률이 계산된 건만 센다. 스냅샷

20거래일 수익률 분포 (전체)

읽는 법

  • 상승 확률이 50% 근처면 "언급"은 방향 정보가 아니다.
  • 초과수익이 0 근처면 종목이 오른 건 시장이 오른 덕이다.
  • 거래량 비율이 1보다 크면 가격과 무관하게 관심은 늘었다.
  • 표본 30건 미만은 참고용으로만 표시한다.

영상의 분위기 대신 과거 기록으로 판단할 근거. 종목별 "전에 떴을 때 어땠나"를 두 번 클릭으로. 개별 유튜버 평가가 아니라 현상의 통계라 분쟁 소지가 적다.

수익 · 운영

개인 구독: 관심 종목 언급 급증 알림 · 채널 상세 옵션. B2B 데이터 API: 종목별 언급량·반응 시계열. 운영비: 전부 무료 티어 공개 API + 하루 1회 배치라 월 수 달러 수준.

지켜야 할 선

채널 실명·성적은 학습용 고지와 함께 · 종목 추천 문구 금지 · 표본 수 항상 표시 · 공개 메타데이터만(자막·댓글 미사용) · 투자 권유 아님 고지 고정.

확장

사건만 바꾸면 같은 틀로 돈다: 트윗("비트코인" 언급 뒤 BTC), 뉴스 헤드라인, 증권사 목표가 상향. 후속 과목에서 자막·LLM 추출로 "사라/팔아라" 방향까지.

막혔던 것과 해결 — AI 가 만든 코드를 어떻게 검증했나

실패한 실험도 데이터였다

  1. 매칭 성공률 26%. 못 잡은 제목 1,304건을 직접 읽어 보니 종목이 아니라 업종·시황 얘기였다 → 테마 사전(업종 → 대표 ETF) 추가, 흔한 단어 스톱리스트 → 62%. 종목 통계와는 분리.
  2. 채널 20개를 누가 고르나. 사람이 고르면 근거가 없다 → 후보 547개를 API 로 측정해 임계값 표를 만들고 2단 규칙으로 51개. 5주차에 넣었던 슈카월드·소수몽키는 언급률 2~4%라 규칙상 제외.
  3. YouTube 쿼터. 검색 API 는 호출당 100유닛이라 20채널 1년치면 하루 한도를 넘는다 → 업로드 재생목록(1유닛)으로 설계, 1년치 4만 4천 편을 약 1,500유닛에.
  4. Render 무료 플랜(512MB). 서비스 4개를 따로 올리면 콜드스타트 4번·주소 4개, 한 컨테이너에 프로세스 5개로 묶으니 기본 메모리 350MB 로 배치 중 OOM → 코드는 4개로 두고 한 프로세스에 마운트해 주소 하나·메모리 절반. 512MB 제한 컨테이너로 재현해 확인했다.
  5. T0 를 언제로 볼 것인가. 게시일 종가로 하면 장 마감 뒤 영상이 "이미 지난 가격"을 쓴다 → 시장별 마감 시각(15:30 KST · 16:00 EST · 업비트 09:00 캔들)으로 첫 거래 가능일을 정하고 테스트로 고정.
  6. AI 코드 검증. 매칭 규칙·사건일·거래량 비율은 pytest 로 규칙을 명시(27개), 계약(OpenAPI)과 구현의 드리프트는 CI 가 막는다. 생성된 코드는 실데이터로 한 바퀴 돌려 숫자가 말이 되는지 보고 반영했다.

정리

외부 API 6개 → 하루 한 번 가공 → 한 가지 질문에 답하는 숫자

유튜브 언급은 많은 사람이 동시에 듣는 "사건"이다. 우리는 그 뒤에 실제로 무슨 일이 있었는지를 1년치 —건으로 셌다. 평가의 핵심인 어떤 소스 · 어떻게 가공 · 무슨 가치를 데이터 페이지와 이 발표의 ③~⑥장에 그대로 담았다.
